# Shared-fate contract: resources, rights, responsibilities

A template for making the platform's social contract explicit, after the "Shared Fate and Responsibility" chapter of *Platform Engineering at Google*. The rule behind it: **the more an ecosystem limits a team's choices, the more liability it can carry for that team.** Fill one in per ecosystem type you actually offer. The examples assume AWS.

## How to use it
1. Decide which ecosystems you offer. Most organisations have two: a golden path (high integration) and raw accounts (low integration).
2. For each capability below, write what the platform provides (**resources**), what the team may choose (**rights**), and what the team must do (**responsibilities**).
3. Publish it. Review it when a team asks for an exemption, joins through an acquisition, or spins out.
4. The most common breach is wanting the rights of the right-hand column with the resources of the left. Name it when you see it.

## The contract

| Capability | Golden path ("walled garden": conformity for leverage) | Raw account ("frontier": autonomy for accountability) |
|---|---|---|
| **Languages and frameworks** | *Rights:* the supported set only. *Resources:* build, scanning, tracing and upgrades for those | *Rights:* anything. *Responsibilities:* build, scan, patch and observe it yourself |
| **Dependencies** | *Resources:* CodeArtifact serving vetted packages; automated updates; bad packages blocked. *Responsibilities:* merge update PRs within N days | *Resources:* a registry and Inspector findings. *Responsibilities:* choose versions, check licences, patch within the published deadlines |
| **Build and artifacts** | *Resources:* hosted, isolated builds; signed provenance. *Rights:* none to bypass | *Responsibilities:* produce signed artifacts yourself if you want to deploy to shared environments |
| **Deployment** | *Resources:* staged rollout, canary analysis, automatic rollback, set by your service tier. *Responsibilities:* keep the head of your main branch releasable | *Rights:* your own process. *Responsibilities:* your own rollback, and your own incident when it fails |
| **Security patching** | *Resources:* base images and runtimes patched centrally; fleet-wide fixes applied for you. *Responsibilities:* don't pin or fork in ways that block them | *Responsibilities:* all of it, within the organisation's deadlines |
| **Reliability** | *Resources:* multi-AZ placement, autoscaling, retry budgets, SLO tracking and alerting | *Resources:* dashboards showing your posture. *Responsibilities:* design, capacity and on-call |
| **Data protection** | *Resources:* backups, restore tests, deletion protection by default | *Responsibilities:* your own backup plan, proven by restore tests |
| **Compliance evidence** | *Resources:* generated by the pipeline | *Responsibilities:* produce it for every audit |
| **Cost** | *Resources:* right-sizing defaults, Graviton by default, cost per service reported | *Responsibilities:* your own optimisation |
| **Support** | Platform team on-call for the path | Best effort, community channel |

## Exemptions
An exemption moves one row from the left column to the right for one service. Record:

| Field | |
|---|---|
| Service and owner | |
| Which guardrail, and why the path can't serve this need | |
| Responsibilities the team takes on | |
| Containment (separate account, sandbox, network boundary) | |
| Expiry date and review owner | |

One exemption is a special case. Five for the same reason is a gap in the platform: treat them as product feedback.

## Moving between ecosystems
Joining the golden path from outside (an acquisition) or leaving it (a special project) is a renegotiation of this contract. Present it as a trade the team is choosing, with the columns side by side, not as a mandate.

## With AI agents writing code
State who is the **guardian of intent**: the person who defines the goal and success criteria for agent-written changes and verifies the result. On the golden path the platform's guardrails hold for agent-written code exactly as for human-written code. In a raw account they don't, so agent use there needs its own review rules.
